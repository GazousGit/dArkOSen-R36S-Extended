## 4. Facts about dArkOSen (from the real 09302026 image and the device)

- Image: p1 BOOT vfat 100 MiB, p2 ROOTFS **btrfs** 8 GiB (319 MiB free when mounted read-write; a read-only mount reports 3 MB), p3 EASYROMS exFAT 100 MiB. First boot (`/boot/expandtoexfat.sh`, on the BOOT partition) grows the root fs, **reformats EASYROMS**, mounts it on `/roms`, runs `pv -n /roms.tar | tar --no-same-permissions --no-same-owner --warning=no-timestamp -xf - -C /`, copies `/tempthemes` into `/roms/themes`, installs the fstab with `/roms`, deletes `/roms.tar` and reboots. So files for `/roms` either go into `/roms.tar` (entries named `roms/...`; this is what `--roms` does) or are seeded from the root fs by our repair service (shipped boot videos: `/usr/share/dArkOSen-Extended/bootvideos` → `/roms/bootvideos`, once, marker `.seeded`).
- `/roms.tar` (260 MB, GNU tar, 2,614 entries) contains the empty system folders plus `tools/` (2,336 files), launch/shutdown images, `backup/`, `pico-8/`, 2 scummvm files, 1 wolf file. **It ships no BIOS files** (`roms/bios/` is an empty folder) and nothing under `roms/psp/`.
- DraStic ships its own replacement BIOS (`/opt/drastic/system/drastic_bios_arm7.bin`, `_arm9.bin`). ECWolf standalone ships `/opt/ecwolf/ecwolf.pk3`; only the libretro `ecwolf` core would need one in `/roms/bios`. PPSSPP: `ppsspp.sh` copies the default settings from `/opt/ppsspp{,-2021}/backupforromsfolder/ppsspp` only when `/roms/psp/ppsspp{,-2021}` does not exist yet (afterwards it only restores `controls.ini` and `ppsspp.ini.sdl`), so a shipped `PSP/SYSTEM` folder must contain the four base files too.
- OTA: `/usr/local/bin/Update.sh` (launched from the ES menu "DOWNLOADS AND UPDATES", which the user could not find) downloads `dArkOSen-Update.sh` from `djparentx/dArkOSen-updates`; each update is a zip unzipped over `/` plus `/tmp/<date>.sh`. Updates can replace `emulationstation.sh` and `es_systems.cfg` (our repair service re-adds the hook/ES entry).
- **09302026 image has no sound in 32-bit emulators** (retrorun32, retroarch32: Dreamcast, Naomi, 32-bit cores) until 09302026b is applied.
- Dialog tools: `/opt/inttools/keys.gptk` maps SDL "a" = Esc, "b" = Enter; `/opt/inttools/gamecontrollerdb.txt` maps SDL "a" to physical A (`a:b1`). So in dArkOSen's own tools **B confirms, A quits**. Our tools follow ES's `InvertButtons` instead.
- ES A/B global switch = `/usr/local/bin/b_swap.sh` (flag `/var/cache/Switch_AB`); the ES part is one `InvertButtons` line in `/home/ark/.emulationstation/es_settings.cfg`; ES writes its settings on exit (edit only while ES is stopped).
- retrorun/retrorun32 read flycast core options from `/home/ark/.config/retrorun.cfg` (`reicast_*`); the shipped retrorun binary knows only the older `retrorun_*` keys (no `retrorun_frameskip`). dArkOS ships two conflicting `reicast_anisotropic_filtering` lines.
- N64 in dArkOSen: `n64.sh EMULATOR CORE ROM`; ES lists `retroarch32` (parallel_n64, the default), `retroarch` (parallel_n64, mupen64plus_next, mupen64plus), `standalone-Rice`, `standalone-Glide64mk2`, `standalone-GlideN64` (`/opt/mupen64plus`, config `/home/ark/.config/mupen64plus/mupen64plus.cfg`). The per-game choice is the `<emulator>`/`<core>` pair in `/roms/n64/gamelist.xml`.
- RetroArch core `mupen64plus_next` ships with **no** core options. Its defaults on this GLES build: 640x480, threaded renderer off, hybrid filter on, framebuffer and LOD emulation on, depth buffer to RDRAM Software, N64 depth compare off, frame duping off. The old `mupen64plus` core ("Mupen64Plus GLES2") shares 31 option names with it (`43screensize`, `EnableFBEmulation`, `EnableCopyColorToRDRAM`, `EnableCopyDepthToRDRAM`, `EnableLegacyBlending`, `aspect`, ...), so one `mupen64plus-*` line drives both. retroarch32 ships 30 `parallel-n64-*` lines (plugin rice, accuracy low, 320x240). Both RetroArch builds have `game_specific_options = "true"`: `~/.config/retroarch{,32}/config/<core name>/<rom name>.opt` replaces the global options for that game (core names: `Mupen64Plus-Next`, `Mupen64Plus GLES2`, `ParaLLEl N64`).
- **The user maintains the N64 compatibility list** (repo `GazousGit/R36S-Game-Compatibility-Lists`, Google Sheet `1FtYqPTjKKdDMlXJqW2gNmPX3IYOPsa4-zvHqTo4YwkQ`, 290 games x 7 emulator/core columns) and keeps the best choice per game in `gamelist.xml` on the card (181 games on 2026-10-11: 106 on the system default, 31 Glide64mk2, 20 Rice, 11 retroarch/mupen64plus, 8 retroarch32, 5 retroarch/parallel_n64). The mupen64plus(_next) columns were tested with the ArkOS wiki GLideN64 settings ("Pixelized" = 320x240), which is why the tool's preset is exactly those settings and nothing more. Never make one emulator the default for everything, and treat per-game settings as the user's data: the tool's `PER_GAME` table only holds fixes recorded in that list (so far Pokemon Stadium on ParaLLEl 32-bit, issue 19).
- PPSSPP: `/usr/local/bin/ppsspp.sh` re-points `/home/ark/.config/ppsspp` to `/roms/psp/ppsspp` (standalone) or `/roms/psp/ppsspp-2021`; per-game settings are `PSP/SYSTEM/<GAMEID>_ppsspp.ini` / `_controls.ini`.
- Saturn: `saturn.sh` runs `/opt/yabasanshiro/yabasanshiro -r 3 -i game` (`-r 3` = "Original", the lowest resolution mode; auto frame skip on by default; `-b saturn_bios.bin` for `standalone-bios`). No other performance switches exist. Alternative to compare: `retrorun32` + `yabasanshiro` core.
- ES themes live in `/roms/themes`; none of the bundled themes has a `videos` system folder except es-theme-switch (the Boot Videos system falls back to text).
- Console with the 22x11 font: 58x21 characters; `dialog` clamps oversized boxes (verified), no sizing bug.

## 6. Personal files in local builds (done 2026-10-11)

The original plan (private repo, files committed under `extended/seed/`, a seeding step in the repair service) was dropped: a fork cannot be made private, and the first boot already has a mechanism that fits.

- `extended/roms/` is laid out like `/roms` and is git-ignored except `README.md` and `.gitignore`. `inject.sh ROOT VIDEOS TAG ROMS_DIR` (from `build-image.sh --roms DIR`) appends every file inside its top folders to the image's `/roms.tar` as `roms/<path>`: never replacing a path the archive already has (compared case-insensitively, EASYROMS is exFAT), refusing when less than 32 MB would stay free on the root fs, and checking the entry count afterwards. dArkOSen's own first boot then extracts them; no device-side code of ours is involved and the space on the root fs is released when the first boot deletes `roms.tar`. The build stamp records `DARKOSEN_EXTENDED_ROMS_FILES`.
- The *Build image* workflow never passes `--roms` and its check job fails if anything other than those two files is tracked under `extended/roms/`. Public releases therefore never contain personal files. **Never `git add -f` anything in that folder; never upload a locally built image.**
- Current content, copied from the card on 2026-10-11 and hash-checked: the whole `bios/` folder except `update118.exe`, `dc/DC - BIOS (All).bin` and `dc/DC - Flash (All).bin` (it includes `dc/dc_nvmem.bin` and the 8 `dc/vmu_save_*.bin` memory cards as they were that day); the 9 boot videos; `psp/ppsspp/PSP/SYSTEM/*` and `psp/ppsspp-2021/PSP/SYSTEM/*` (top-level files only, no cache, saves or cheats).
- Verified on the real 09302026 image: 1,124 files (84 MB) appended, `btrfs check` clean, 235 MiB still free; replaying the first-boot `tar` command gives all 1,124 files byte-identical and all 2,614 upstream entries intact. Not replayed onto an exFAT filesystem (exfat-fuse would not mount in WSL) and not yet flashed to a card.
- The built image is `D:\ClaudeFolder\R36S-dArkOS-Fork\builds\dArkOSen-Extended_R36_09302026-private.img` (8.2 GB, outside the repository; built with `--name dArkOSen-Extended_R36_09302026-private`). Like the public image it does not include OTA 09302026b: run *Update-dArkOSen* once after flashing.
- BIOS gaps left as they were: `scph5501.bin` (only DuckStation/SwanStation want it; other US BIOS files are present), `ecwolf.pk3` for the libretro core (the standalone has its own), `colecovision.rom` and DS naming (no games for either on the card).

## 7. How to work on this (practical)

- Windows file tools write CRLF; before running anything in WSL convert: `wsl -d Ubuntu -u root -e bash -c 'cd /mnt/d/ClaudeFolder/R36S-dArkOS-Fork/dArkOSen-R36S-Extended && sed -i "s/\r$//" <files>'`. Git normalizes on commit (`.gitattributes` `text=auto eol=lf`). Never `git add -A`; add paths.
- Tests: `wsl -d Ubuntu -u root -e bash -c 'cd /mnt/d/.../dArkOSen-R36S-Extended && bash extended/tests/run-tests.sh'` (221 checks; shellcheck, ffmpeg, btrfs-progs, 7z, jq, sshpass, dialog are installed in WSL).
- WSL scratch: `/root/darkosen-ext/` (`dl/` upstream 7z parts, `orig/` extracted 8.2 GB image, `work/` build scratch, `ota/` the 09302026b zip, `tools/actionlint`, `tools/inspect-image.sh` and `tools/verify-image.sh` from the roms.tar work, `inspect/roms-tar.names` the upstream archive listing, `mnt-ro/` read-only mounts of the image for inspection).
- Local full build with the personal files: `cp --sparse=always /root/darkosen-ext/orig/dArkOSen_R36_09302026.img /root/darkosen-ext/work/build.img`, then from the repo root `bash extended/build/build-image.sh --img /root/darkosen-ext/work/build.img --tag 09302026 --workdir /root/darkosen-ext/work --videos extended/bootvideos --roms extended/roms --no-pack` (20 s; result in `work/img/`). Unmount any inspection mount of the original image first: btrfs refuses to mount a second copy of the same filesystem ID and the build then reports "could not find the dArkOSen root filesystem".
- Device: `sshpass -p ark ssh ark@192.168.1.159`; `ark` has passwordless sudo. Only reachable when the card is in the device and it is on.
- GitHub: the GitHub connector token reads but cannot create PRs; PRs are created with the token from Git Credential Manager (`git credential fill`), not printed. No `gh` CLI locally. Workflow runs/annotations: `api.github.com/repos/GazousGit/dArkOSen-R36S-Extended/actions/runs` and `.../check-runs/<job id>/annotations` (public today; need the token once private).
- Workflow behaviour: push to `main` or `ext/**` touching `extended/` runs the check; branch runs publish drafts or skip; `main` promotes drafts and rebuilds when the `extended/` tree hash changed; `workflow_dispatch` has `tag`, `force`, `draft`, `level`.
