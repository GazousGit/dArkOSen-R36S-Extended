## 4. Facts about dArkOSen (from the real 09302026 image and the device)

- Image: p1 BOOT vfat 100 MiB, p2 ROOTFS **btrfs** 8 GiB (319 MiB free when mounted read-write; a read-only mount reports 3 MB), p3 EASYROMS exFAT 100 MiB. First boot (`/boot/expandtoexfat.sh`, on the BOOT partition) grows the root fs, **reformats EASYROMS**, mounts it on `/roms`, runs `pv -n /roms.tar | tar --no-same-permissions --no-same-owner --warning=no-timestamp -xf - -C /`, copies `/tempthemes` into `/roms/themes` and deletes `/tempthemes`, installs the fstab with `/roms`, deletes `/roms.tar` (09302026 only: in 10152026 that line is commented out, `roms.tar` stays because *Switch to SD2 for Roms* reuses it) and reboots. The script works from the end of partition 2 (pass 1: `sfdisk -N 3 ", +"`; pass 2: delete p3, `growpart --free-percent` p2 to about 11 GB, `btrfs filesystem resize max /`, new p3 from the end of p2, `mkfs.exfat`), so a bigger p2 in the image is fine. 10152026 ships themes art-book-next-es-demake, freeplay, minimal-arkos, replica, retrodark, switch, xmb-fcamod-main; it dropped es-simple-theme, es-theme-nes-box and es-theme-retrooz (silently, not in its release notes). So files for `/roms` either go into `/roms.tar` (entries named `roms/...`; this is what `--roms` does) or are seeded from the root fs by our repair service (shipped boot videos: `/usr/share/dArkOSen-Extended/bootvideos` → `/roms/bootvideos`, once, marker `.seeded`).
- `/roms.tar` (260 MB, GNU tar, 2,614 entries) contains the empty system folders plus `tools/` (2,336 files), launch/shutdown images, `backup/`, `pico-8/`, 2 scummvm files, 1 wolf file. **It ships no BIOS files** (`roms/bios/` is an empty folder) and nothing under `roms/psp/`.
- DraStic ships its own replacement BIOS (`/opt/drastic/system/drastic_bios_arm7.bin`, `_arm9.bin`). ECWolf standalone ships `/opt/ecwolf/ecwolf.pk3`; only the libretro `ecwolf` core would need one in `/roms/bios`. PPSSPP: `ppsspp.sh` copies the default settings from `/opt/ppsspp{,-2021}/backupforromsfolder/ppsspp` only when `/roms/psp/ppsspp{,-2021}` does not exist yet (afterwards it only restores `controls.ini` and `ppsspp.ini.sdl`), so a shipped `PSP/SYSTEM` folder must contain the four base files too.
- OTA: `/usr/local/bin/Update.sh` (launched from the ES menu "DOWNLOADS AND UPDATES", which the user could not find) downloads `dArkOSen-Update.sh` from `djparentx/dArkOSen-updates`; each update is a zip unzipped over `/` plus `/tmp/<date>.sh`. Updates can replace `emulationstation.sh` and `es_systems.cfg` (our repair service re-adds the hook/ES entry).
- **09302026 image has no sound in 32-bit emulators** (retrorun32, retroarch32: Dreamcast, Naomi, 32-bit cores) until 09302026b is applied.
- Dialog tools: `/opt/inttools/keys.gptk` maps SDL "a" = Esc, "b" = Enter; `/opt/inttools/gamecontrollerdb.txt` maps SDL "a" to physical A (`a:b1`). So in dArkOSen's own tools **B confirms, A quits**. Our tools follow ES's `InvertButtons` instead.
- ES A/B global switch = `/usr/local/bin/b_swap.sh` (flag `/var/cache/Switch_AB`); the ES part is one `InvertButtons` line in `/home/ark/.emulationstation/es_settings.cfg`; ES writes its settings on exit (edit only while ES is stopped).
- retrorun/retrorun32 read flycast core options from `/home/ark/.config/retrorun.cfg` (`reicast_*`); the shipped retrorun binary knows only the older `retrorun_*` keys (no `retrorun_frameskip`). dArkOS ships two conflicting `reicast_anisotropic_filtering` lines.
- N64 in dArkOSen: `n64.sh EMULATOR CORE ROM`; ES lists `retroarch32` (parallel_n64, the default), `retroarch` (parallel_n64, mupen64plus_next, mupen64plus), `standalone-Rice`, `standalone-Glide64mk2`, `standalone-GlideN64` (`/opt/mupen64plus`, config `/home/ark/.config/mupen64plus/mupen64plus.cfg`). The per-game choice is the `<emulator>`/`<core>` pair in `/roms/n64/gamelist.xml`.

Its defaults on this GLES build: 640x480, threaded renderer off, hybrid filter on, framebuffer and LOD emulation on, depth buffer to RDRAM Software, N64 depth compare off, frame duping off. The old `mupen64plus` core ("Mupen64Plus GLES2") shares 31 option names with it (`43screensize`, `EnableFBEmulation`, `EnableCopyColorToRDRAM`, `EnableCopyDepthToRDRAM`, `EnableLegacyBlending`, `aspect`, ...), so one `mupen64plus-*` line drives both. retroarch32 ships 30 `parallel-n64-*` lines (plugin rice, accuracy low, 320x240). Both RetroArch builds have `game_specific_options = "true"`: `~/.config/retroarch{,32}/config/<core name>/<rom name>.opt` replaces the global options for that game (core names: `Mupen64Plus-Next`, `Mupen64Plus GLES2`, `ParaLLEl N64`).

## 6. Personal files in local builds (done 2026-10-11)

The original plan (private repo, files committed under `extended/seed/`, a seeding step in the repair service) was dropped: a fork cannot be made private, and the first boot already has a mechanism that fits.

- `extended/roms/` is laid out like `/roms` and is git-ignored except `README.md` and `.gitignore`. `inject.sh ROOT VIDEOS TAG ROMS_DIR` (from `build-image.sh --roms DIR`) appends every file inside its top folders to the image's `/roms.tar` as `roms/<path>`: never replacing a path the archive already has (compared case-insensitively, EASYROMS is exFAT), refusing when less than 32 MB would stay free on the root fs, and checking the entry count afterwards. dArkOSen's own first boot then extracts them; no device-side code of ours is involved (since 10152026 `roms.tar` and these files stay on the root fs after the first boot). The build stamp records `DARKOSEN_EXTENDED_ROMS_FILES`. Since 2026-10-16 (branch `ext/themes-view-reminder`): `themes/<name>/` goes to `/tempthemes` instead (copied to `/roms/themes` and deleted by the first boot; falls back to `roms.tar` when the image has no `/tempthemes`), `extended/roms/es_settings.cfg` lines (ES's own format) replace or add settings in the image's `es_settings.cfg` after the N64 default (stamp `DARKOSEN_EXTENDED_THEMES`, `DARKOSEN_EXTENDED_ES_SETTINGS`), and when the `--roms` files would not fit, `build-image.sh` first grows the root partition by their raw size + 48 MB in 64 MiB steps (`grow-root.sh`: image +N MiB, p2 +N, p3 moved with its data, same disk id; then `btrfs filesystem resize max`). The user's personal set then: the three dropped themes from 09302026 and `GamelistViewStyle = video` (private builds only, the user's choice; `FolderViewMode` stays `always`: dArkOSen's ES has no per-system folder setting, `FileData.cpp` reads it globally).
- **10152026 has only 95 MB free on the root fs** (09302026: 319 MB). Since PR #6 `build-image.sh` mounts the btrfs root with `compress-force=zlib:1` (dArkOSen's own fstab uses `compress=zlib:1`; its 4.4 kernel reads zlib), and `inject.sh` estimates the compressed size with `gzip -1` +10 % when the target is mounted with compression, then re-checks the real free space after `sync`. The current personal set (84 MB) takes 54 MB; 41 MB stay free. ### 8.4 Findings

- **Legacy hack (`flycast32_rumble_hack`)**: the speed comes from metallic77's SH4 cycle multiplier (`reicast_sh4clock`, default `d12` = 165 MHz; our build also reads plain MHz). Not yet judged in play by the user (GTA2, speed vs stock).
- **Modern flycast as a 32-bit core** — two bugs found and fixed:
  1. Build: a command-line `CMAKE_CXX_FLAGS` replaced the toolchain's CPU flags, so the core was Debian armhf default (Thumb-2, no NEON); the dynarecs `BL` into C++ from A32 code and aborted in `retro_init` (vixl `Assembler::bl` -> `UnimplementedDelegate`). Fixed in `build-modern.sh` (dArkOSen-Extended `b1110cc`).
  2. Upstream UB in `core/hw/mem/addrspace.cpp`: `addr <<= iirf` shifts by the whole tagged page entry; GCC 14 on armhf folds it to 0, every RAM read lost its in-page offset, the BIOS never ran (black screen, SH4 PC sliding through memory, dynarec and interpreter alike). Fixed by `iirf & HANDLER_MAX` (fork `e0e960683`); worth offering upstream.
  - With both fixes: Dreamcast BIOS animation renders; RE2 reaches the "SEGA / Powered by Windows CE" screen at 15 s, then glibc **"double free or corruption (!prev)"**; **Code Veronica hangs at once** (RetroArch must be SIGKILLed). Earlier builds also hit a SIGSEGV in a Thumb system library when RetroArch unloads the core.
  - Own option prefix since fork commit `a873b38cf` (2026-10-16 evening): `CORE_OPTION_NAME` = `flycast` (ROCKNIX does the same), so its `flycast_*` keys no longer collide with the legacy cores' `reicast_*` in the shared `retroarch32/retroarch-core-options.cfg`, which RetroArch rewrites at every unload. dArkOSen's `reicast_*` values (320x240, HLE BIOS off, ...) do not reach it any more: its defaults are the LOW_END ones. VMU saves stay in `<saves>/reicast/`.
- **64-bit standalone flycast v2.7 (`standalone-Flycast`), user test**: RE2 at 10-30 fps (Dreamcast = 50/60), 50/60 Hz prompt, brightness prompt, then a frozen black screen (its menu still opens). So even modern flycast on the best-tested ARM path does not run RE2 on the R36S, and is far from full speed: **WinCE games look out of reach on this hardware for now**; a 32-bit build would not close that gap.
- Rumble: on dArkOSen the pad driver ("GO-Super Gamepad") owns the motor and offers force feedback (EV_FF/FF_RUMBLE); `/sys/class/pwm/*/pwm0` never exists, so the sysfs motor code in both cores is a no-op there; rumble goes through the frontend. dArkOSen's retroarch32 options ship `reicast_enable_purupuru = "disabled"`.
- The user's whistling noise: random, only with ES background music; likely the audio amplifier, unrelated to this work.

### 8.5 How to test a core on the console without side effects

- Stop ES first (`sudo systemctl stop emulationstation`), set governors with `sudo perfmax performance <rom>` (over SSH the reminder stays quiet), restart ES and run `perfnorm` afterwards. Never run two sessions' builds at once: `/root/darkosen-ext/tools/build10.sh` runs `losetup -D`.
- Run `/opt/retroarch/bin/retroarch32 -c ~/.config/retroarch32/retroarch.cfg --appendconfig=<file> -L <core> <rom>` with an appendconfig holding `config_save_on_exit = "false"`, `savestate_auto_load = "false"`, `savestate_auto_save = "false"`, `core_options_path = "/tmp/fc-opts.cfg"` (a copy of the real options), `game_specific_options = "false"`, `video_threaded = "false"`, `screenshot_directory = "/tmp/shots"`, `sort_screenshots_by_content_enable = "false"`. Screenshots on demand: `echo -n SCREENSHOT > /dev/udp/127.0.0.1/55356` (network commands are on, port 55356); check them against the stock core first. Wrap in `timeout -k 5 N` (retrorun32 ignores SIGTERM).
- Debugging: no gdb/strace on the device. `tools/abort-trace.c` (LD_PRELOAD, build in the chroot) prints the stack (lib+offset, exported names) when `abort()` is called; glibc's own heap-corruption aborts bypass it. In release builds flycast compiles out `INFO_LOG`/`DEBUG_LOG`: use `NOTICE_LOG` for temporary diagnostics. The modern core is linked with `-s` (`LINK_FLAGS_RELEASE`); for symbols, build once without it (`-g` does not change the code).
